# Постачання «Асістента» в закритий контур

Документ описує повний шлях: збірка → носій → встановлення на машині викладача →
діагностика. Розрахований на те, що на цільовій машині **немає мережі й немає
прав адміністратора**.

---

## 1. Що постачається

| Компонент | Розмір | Звідки |
|---|---:|---|
| `Asistent_<версія>_x64-setup.exe` (Windows) | ~900 МБ | `.github/workflows/release.yml` |
| `Asistent_<версія>_aarch64.dmg` (macOS) | ~900 МБ | те саме |
| Тека `models/` + `manifest.json` | 1.2–1.8 ГБ | `scripts/fetch_models.py` |
| `SHA256SUMS.txt` | — | генерується в релізі |
| Акт постачання з контрольними сумами **на папері** | — | розділ 5 |

Інсталятор Windows несе **офлайн-інсталятор WebView2** (+127 МБ). Це свідома
плата: Windows 11 має WebView2 передвстановлено, але редакції Windows 10
Enterprise LTSC — ні, а `downloadBootstrapper` у закритому контурі просто зависає.

Моделі можна класти **в інсталятор** або **на носій окремо**. Другий варіант —
дефолтний: один інсталятор обслуговує кілька машин, а 1.8 ГБ копіюються один раз.

---

## 2. Збірка

Крос-компіляція неможлива: Tauri прямо це документує, а MSI вимагає Windows, бо
WiX працює лише там. **Кожна ОС збирається на своїй ОС** — на GitHub Actions
матрицею `windows-latest` + `macos-26`, локально на відповідній машині.

```bash
# 0. Одноразово: uv, Rust, Node 22
#    https://docs.astral.sh/uv/  https://rustup.rs/

# 1. Моделі (потрібна мережа — це єдиний етап, де вона потрібна взагалі)
python scripts/fetch_models.py --models-dir src-tauri/resources/models
python scripts/verify_models.py --models-dir src-tauri/resources/models

# 2. Релокований Python-рантайм (uv + python-build-standalone, НЕ PyInstaller)
python scripts/build_runtime.py --out src-tauri/resources/runtime

# 3. Фронтенд
npm --prefix frontend ci && npm --prefix frontend run build

# 4. Інсталятор
npx @tauri-apps/cli@2 build
```

Артефакти:
`src-tauri/target/release/bundle/nsis/*-setup.exe`,
`src-tauri/target/release/bundle/dmg/*.dmg`.

Перед підписанням розмір перевіряється бюджетом:

```bash
python scripts/check_size_budget.py --max-mb 900 src-tauri/target/release/bundle/nsis/*-setup.exe
```

Перевищення бюджету майже завжди означає одне: у рантайм заїхало колесо `torch`
з CUDA-залежностями. CPU-torch — це ~124 МБ на Windows і ~127 МБ на macOS;
багатогігабайтний варіант з'являється, лише якщо навмисно тягнути колеса з
`download.pytorch.org`.

## 3. Носій

```
USB/
├── Asistent_0.1.0_x64-setup.exe
├── SHA256SUMS.txt
├── models/                 ← пласке дерево + manifest.json
├── LMStudio-<версія>.exe   ← окремо; ставиться до Асістента
├── models-llm/             ← GGUF генератора (MamayLM 12B Q4_K_M, 7.3 ГБ)
└── ІНСТРУКЦІЯ.txt
```

Тека `models/` копіюється **як є**. Пласке дерево з контрольними сумами обране
навмисно замість кеш-розкладки HuggingFace: кеш HF тримає файли симлінками, а
на Windows без Developer Mode створення симлінка непривілейованим користувачем
дає `WinError 1314` — тобто саме на машині викладача.

Файлова система носія — **exFAT**. FAT32 не візьме 7-гігабайтний GGUF.

## 4. Встановлення

### 4.1 Windows 11

```bat
:: тихе встановлення, БЕЗ прав адміністратора (NSIS installMode perUser)
Asistent_0.1.0_x64-setup.exe /S
```

Ставиться у `%LOCALAPPDATA%\Programs\Asistent`, дані — у `%LOCALAPPDATA%\Asistent`.
Жодних записів у `Program Files` і `HKLM` — саме тому працює без адміністратора.

Далі — **майстер першого запуску**, 5 кроків:

1. вибір теки даних (за замовчуванням `%LOCALAPPDATA%\Asistent`);
2. **вказати теку моделей** з носія — застосунок скопіює її в теку даних і
   перевірить SHA-256 кожного файлу (`scripts/verify_models.py`);
3. детекція LM Studio і рекомендація моделі за обсягом VRAM;
4. створення першого асистента;
5. перше завантаження матеріалів.

Перевірити моделі вручну можна будь-коли:

```bat
"%LOCALAPPDATA%\Programs\Asistent\runtime\python.exe" scripts\verify_models.py ^
    --models-dir "%LOCALAPPDATA%\Asistent\models"
```

**Куди НЕ можна класти теку даних.** Застосунок відмовиться відкрити базу на
UNC-шляху (`\\server\...`), мережевому диску або в теці OneDrive / Dropbox /
Google Drive: SQLite поверх SMB і хмарної синхронізації є задокументованим
джерелом пошкодження файлів. На доменній машині «Документи» часто
перенаправлені саме в OneDrive — це реальний, а не теоретичний випадок.

### 4.2 macOS (Apple Silicon)

```bash
hdiutil attach Asistent_0.1.0_aarch64.dmg
cp -R /Volumes/Asistent/Asistent.app /Applications/
hdiutil detach /Volumes/Asistent

# перевірка, що нотаризація зі стейплом реально спрацювала
spctl --assess --type execute --verbose=4 /Applications/Asistent.app
```

Якщо `spctl` відхиляє застосунок — інсталятор не нотаризований; ставити його
можна лише через контекстне меню «Відкрити» з підтвердженням. У CI ця перевірка
виконується автоматично (`scripts/smoke_installer.py`), щоб проблема не
доїжджала до Mac викладача у вигляді «застосунок пошкоджено».

## 5. Контрольні суми на папері

У закритому контурі підпис коду перевірити нічим: немає доступу до CRL/OCSP.
Тому цілісність постачання підтверджується **актом на папері**.

```bash
# на машині збірки
shasum -a 256 Asistent_0.1.0_x64-setup.exe          # macOS/Linux
certutil -hashfile Asistent_0.1.0_x64-setup.exe SHA256   # Windows
```

Суму інсталятора і **відбиток каталогу моделей**
(`python scripts/fetch_models.py --print-fingerprint`) вносять в акт, який
підписують здавач і приймач. На цільовій машині перед запуском:

```bat
certutil -hashfile Asistent_0.1.0_x64-setup.exe SHA256
```

Розбіжність хоча б в одному символі — носій не використовувати.

## 6. Windows Defender

### 6.1 Виняток для теки даних

Індексація 1000-сторінкового підручника — це десятки тисяч записів у
`%LOCALAPPDATA%\Asistent`. Realtime-сканування кожного з них подвоює час
індексації. Виняток **лише для теки даних**, не для теки програми:

```powershell
# від імені адміністратора, силами ІТ-відділу академії
Add-MpPreference -ExclusionPath "$env:LOCALAPPDATA\Asistent"
```

Якщо адміністратор недоступний — застосунок працюватиме, просто повільніше.

### 6.2 Хибне спрацювання

Ми не використовуємо PyInstaller саме тому, що його самозакорковуваний
бутстрап — рівно той механізм, який дає хибні спрацювання евристик.
python-build-standalone постачає звичайний `python.exe` і звичайні DLL.
Але новий непідписаний бінарник із низькою репутацією SmartScreen усе одно
може блокувати.

Порядок дій:

1. зафіксувати точну назву детекту (Захист від вірусів → Журнал);
2. подати файл як хибне спрацювання:
   **Microsoft Security Intelligence → Submit a file for analysis**
   (`https://www.microsoft.com/wdsi/filesubmission`), тип — «Software developer»;
3. до відповіді (зазвичай 1–3 доби) — тимчасовий виняток для файлу інсталятора;
4. після відповіді — повторно завантажити той самий файл і переконатися, що
   детект зник.

## 7. Підпис коду: чесний стан справ

**Azure Artifact Signing (колишній Azure Trusted Signing) недоступний фізичним
особам з України** — сервіс приймає індивідуальних розробників лише зі США й
Канади. Тому доступні три шляхи:

| Варіант | Вартість | Наслідок |
|---|---|---|
| OV-сертифікат (Sectigo / SSL.com) із ключем у хмарному HSM | ~300–500 USD/рік | Працює. З 01.03.2026 максимальний строк сертифіката — 460 днів, тобто перевипуск щороку. Ключ **зобов'язаний** лежати в HSM або на токені — файлові .pfx більше не видають. |
| EV-сертифікат | дорожче | Додатково знімає попередження SmartScreen одразу, без напрацювання репутації. |
| **Без підпису + акт із контрольними сумами** | 0 | Прийнятно **саме для закритого контуру**: доставка носієм, встановлення під контролем ІТ-відділу, цілісність підтверджена папером. Ціна — попередження SmartScreen при першому запуску. |

Для НДР із доставкою на USB третій варіант є робочим. Рішення фіксується в акті
впровадження.

macOS складніший: без нотаризації Gatekeeper блокує запуск, і обійти це можна
лише вручну на кожній машині. Якщо цільові Mac-и є в контурі — нотаризація
обов'язкова, а це потребує платного Apple Developer Program (99 USD/рік).

## 8. Оновлення й видалення

**Автооновлювача немає навмисно** (`createUpdaterArtifacts: false`, плагіна
`updater` немає в залежностях). Продукт, який ставлять з USB у закритий контур,
не має права ходити в мережу за оновленням. Оновлення = новий інсталятор з
носія; він завершить запущений застосунок і перезапише файли програми,
**не чіпаючи теку даних**.

Видалення (Параметри → Програми → Асістент) прибирає лише програму. База знань
у `%LOCALAPPDATA%\Asistent` лишається — переіндексувати корпус коштує години.
Видаляти її потрібно вручну й свідомо.

## 9. Діагностика

| Симптом | Куди дивитись |
|---|---|
| Вікно застосунку не з'являється / діалог «Асістент не зміг запуститися» | `sidecar.log` — у діалозі вже показано його хвіст. Це Python-traceback, який убив старт. |
| Не зрозуміло, на якому порту API | `api-port.json` поруч із логом: `{"port":…, "pid":…}` |
| «Модель не завантажується» | `python scripts/verify_models.py --models-dir <тека> --json` |
| Асистент відповідає «не знайдено в матеріалах» на очевидні питання | Перевірити, що індексація завершилась, і що вибрано правильну колекцію |
| LM Studio не знайдено | Він має слухати на `127.0.0.1:1234`; мережевий гард дозволяє **лише** петлю назад |

Розташування логів:

* Windows — `%LOCALAPPDATA%\Asistent\logs\`
* macOS — `~/Library/Logs/Asistent/`

**Діагностичний пакет.** Чекбокс «Включити назви документів» вимкнений за
замовчуванням; вміст документів не включається ніколи. Це військова академія —
назви матеріалів самі по собі можуть бути чутливими.

## 10. Контрольний список приймання

- [ ] Контрольні суми інсталятора й відбиток моделей звірено з паперовим актом
- [ ] `verify_models.py` пройшов без помилок (повна перевірка, не `--quick`)
- [ ] LM Studio встановлено, модель генератора завантажується без помилки guardrail
- [ ] Проіндексовано один реальний підручник; зафіксовано хв/сторінку
- [ ] Клік по цитаті відкриває PDF на правильній сторінці з підсвіченим фрагментом
- [ ] Питання, відповіді на яке в корпусі немає, дає відмову, а не вигадку
- [ ] Питання, що вимагає трьох підручників, цитує щонайменше три документи
- [ ] Після закриття застосунку в диспетчері задач не лишилось `python.exe`
